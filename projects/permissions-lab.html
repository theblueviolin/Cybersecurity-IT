📖 Access Control & Least Privilege Principle

What is Least Privilege?

Least Privilege is a fundamental security principle: every user, application, and system component should have the minimum level of access required to perform their function. This reduces risk by limiting the damage an attacker can do if they compromise a user account.

Why Least Privilege Matters:

  • Limits damage from compromised accounts: If an employee's account is hacked, attacker can only access what that employee can access
  • Reduces insider threats: Prevents accidents (e.g., accidental file deletion) and malicious acts
  • Compliance requirements: HIPAA, GDPR, SOC 2 all mandate least privilege principles
  • System stability: Limits accidental changes that could break systems

Real-World Examples:

  • Database passwords should NOT be hardcoded in applications
  • Service accounts should have minimal permissions (not admin)
  • Contractors should have temporary, limited access
  • Developers should NOT have production database write access
  • Interns should only see non-sensitive data

Implementation Methods:

  • Role-Based Access Control (RBAC): Users assigned to roles with predefined permissions
  • Attribute-Based Access Control (ABAC): Access based on user attributes, resource attributes, and environment
  • Just-In-Time (JIT) Access: Temporary elevated access when needed, revoked after use
  • Multi-Factor Authentication (MFA): Extra security layer for sensitive access
